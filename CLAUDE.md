# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Rust library built as a Python extension (PyO3 + maturin, no poetry). It exposes one function, `solve(input_json, max_delta_soc, max_duration)`, for electric-bus vehicle scheduling. The input format is in `README.md`.

## Commands
- Rust tests: `cargo test`, or `cargo test <name>` for one test. Run from the repo root, because fixtures load via relative paths.
- Python tests need the built extension: `pip install networkx . && python -m unittest discover test`
- rustfmt and black run automatically through hooks in `.claude/settings.json`. Tools that aren't installed are skipped.

## Versioning
Every PR bumps the version according to SemVer. The API is `solve`'s signature, its JSON input format and the meaning of its output.
- patch: no API change
- minor: backwards-compatible API change, e.g. a new optional parameter
- major: breaking change, i.e. callers must change

The version lives only in `Cargo.toml`, since `pyproject.toml` reads it dynamically. Also update the `eflips-schedule-rust` entry in `Cargo.lock`. Pushing a `vX.Y.Z` tag publishes to PyPI.

## Gotchas
- Rust and Python tests assert exact rotation counts per subgraph. If a change alters them, report it as a behavior change; don't just update the numbers.
- `.github/workflows/CI.yml` is generated by `maturin generate-ci github`. Regenerate it; don't hand-edit it.
- `src/main.rs` (`cargo run`) is a debug harness that reads `/tmp/graph.json`. The `*.json` files in the repo root are debug dumps, not fixtures.
- Ask before adding a crate or Python dependency.
